# 04｜結果與限制

## 事件多、帳號多、連線多是不同的量

| 網站事件分類 | 清理後事件列數 | 不同帳號數 | 在該類事件中跨至少兩個專案的帳號數 |
| --- | ---: | ---: | ---: |
| 全部所選事件 | 12,742 | 1,379 | 93 |
| Issue | 1,070 | 538 | 23 |
| 討論 | 4,474 | 1,035 | 62 |
| PR | 1,874 | 388 | 27 |
| Review | 5,324 | 175 | 27 |

Review 事件列數多於 PR，但出現的不同帳號較少。可以說「在本定義與期間內，審查相關事件由較小的帳號集合產生」，不能把不同類型的一筆事件當成相同工作量，也不能把 5,324 說成審查了 5,324 份不同 PR。

## 三組角色重疊

| 比較 | 共同帳號（交集） | 至少一種活動的不同帳號（聯集） | Jaccard |
| --- | ---: | ---: | ---: |
| Issue 與 PR | 125 | 801 | 0.156 |
| Issue 與 Review | 69 | 644 | 0.107 |
| PR 與 Review | 127 | 436 | 0.291 |

本研究這三組比較中，PR 與 Review 的帳號集合相對最接近；Issue 與 Review 較少重疊。這些分數沒有附統計檢定或信賴區間，不能說差異已達統計顯著，也沒有證明有人從一種角色轉換成另一種。

## 如何讀 93 與 59？

- 93 是「在至少兩個選定專案留下任一所選事件」的帳號。
- 59 是其中又同時有「Issue／討論」和「PR／Review」活動的帳號。
- `93 / 1,379 ≈ 6.7%` 是保留帳號中跨專案的比例。
- `59 / 93 ≈ 63.4%` 是跨專案帳號中又跨兩類活動的比例；`59 / 1,379 ≈ 4.3%` 是全體保留帳號中的比例。報告比例時必須說明分母。

「跨角色」只是可觀察的活動組合，不代表已確認帳號的職務、專業身分或協調成果。

## 四種中心度顯示不同的位置

以下為全部事件核心的帳號分數，分數已按分析輸出四捨五入；同分只按名稱排列，排列先後不表示差異。

| 指標 | 排名前列的例子 | 可以怎麼說 |
| --- | --- | --- |
| Degree | faaany、steveepreston、stevhliu、Wauplin 均為 5 | 這四個帳號都連到五個選定專案 |
| Closeness | stevhliu、Wauplin 均約 0.48571 | 在這張核心中，到其他節點的最短路徑整體較短 |
| Betweenness | Wauplin 約 0.01591，stevhliu 約 0.01262 | 在其他節點最短路徑上所占比例較高 |
| Eigenvector | faaany、steveepreston 的帳號內縮放值均為 1；stevhliu 約 0.91027 | 連結結構使這些帳號取得較高的特徵向量分數 |

Wauplin 的 degree 也是 5，但 eigenvector 約 0.82850。因此連到相同數量的專案，不保證 eigenvector 相同；連到哪些專案也會影響結果。不能據此評判帳號能力，亦不能比較某人的 eigenvector 0.8 和另一人的 betweenness 0.02，說前者「重要四十倍」。

完整數值見[中心度 CSV](../docs/repro/centrality-scores.csv)。中心度計算涵蓋核心的所有節點，網站圖為可讀性最多顯示 40 個示例帳號；挑選示例不會把中心度改算在那 40 個帳號上。

## 補充的審查者 → 作者關係

經欄位可辨識、非自我指向等篩選後，保留 2,058 筆有向審查事件，共 675 種不同的「審查者、PR 作者」有序配對，涉及 108 個審查者帳號與 339 個作者帳號。兩個帳號集合可能重疊，所以 108＋339 不能直接當成不同人數。

同一對帳號可重複出現，因此 2,058 是事件列數、675 是不同配對數。箭頭表示審查對象的方向，並不證明權力、指導或實際影響方向。這裡沒有把全部 5,324 筆 Review 分類事件都當成人際有向邊。

## 說明結論時必須保留的限制

1. **觀察邊界有限。**只有十個目的性選取的儲存庫、2025 年 1 月、五種公開事件。單一專案帳號可能在未選入的 repo 很活躍。
2. **公開紀錄不是完整工作。**不包含私人或線下活動，也沒有分析每筆修改與對話內容。
3. **帳號不等於真人。**已排除可辨識機器人，但可能仍有自動化、共用或改名帳號；也沒有真人身分認證。
4. **沒有逐筆核對鏡像。**原始快照未保存唯一 event ID，沒有完成逐時原檔比對或依 event ID 的去重。不能保證無重複或遺漏。
5. **中心度依網絡定義而變。**單一專案帳號未進入中心度核心，得到的是跨專案核心的位置。沒有比較多種門檻、月份或權重的敏感度分析。
6. **結果是描述性的。**沒有證明因果、品質、工作量或個人價值，也沒有統計顯著性的主張。

## 報告可以怎麼收尾？

> 在這十個專案、這一個月的公開事件中，不同活動的帳號只有部分重疊。大多數帳號只出現在一個選定專案，少數帳號跨越專案，其中一部分同時參與社群類與程式碼類活動。不同中心度提供不同的位置資訊；我們把這些結果當成協作結構的描述，並保留資料與網絡邊界的限制。
